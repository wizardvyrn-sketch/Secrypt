# Security Policy / セキュリティポリシー

**English** | [日本語](#日本語)

## Reporting a vulnerability

Secrypt is a hobby project whose code was written entirely by generative AI and has **not been independently security-audited**. The author provides **no support and no response-time commitment**; a report may go unanswered or unfixed.

If you still want to report a problem:

1. Use GitHub's **Private vulnerability reporting** ("Security" tab → "Report a vulnerability") if it is enabled on this repository.
2. Otherwise open an Issue **without exploit details or any real data**, saying only that you have a security report; details can be arranged afterwards.

Never post a real vault file (`*.pwmv`), key file (`*.pwmk`), recovery code, PIN, password or log that contains personal data.

Only the latest release is considered. You are free to fork and fix it yourself under the [license](LICENSE) (MIT).

## What is in scope

Secrypt is designed so that **a leaked vault file alone, or a leaked password alone, is not enough to open it**, and so that the PIN of the TPM method cannot be brute-forced offline. The design and its limits are written down in [docs/02-threat-model.md](docs/02-threat-model.md) and [docs/03-key-management.md](docs/03-key-management.md) (Japanese). Reports about a PC that is already compromised (malware, keyloggers, a debugger attached by an administrator) are out of scope — see below.

## Known limitations

Please read these before relying on Secrypt for anything important.

- **Removing an unlock method does not change the master key.** When you remove an unlock method (for example a lost key file), regenerate the recovery code, or change the PIN, the vault's master key stays the same; only the old way of opening it is dropped from the file. Anyone who has **a copy of the vault file made before the removal** *and* the removed method's secret (the lost key file + its password, the old recovery code, or the old PIN on the same PC) can still open that old copy — and the master key it yields also opens the current file.
  - Secrypt deletes its own automatic backups (`vault.pwmv.bak1`–`.bak5`) on this PC when you do this, and says so before you confirm.
  - It **cannot delete copies outside the app**: cloud sync, File History, backups on external drives. Delete those yourself if a key may have been lost or seen.
  - Master-key rotation (re-encrypting everything with a new key) is **not implemented yet** (planned; see [docs/06-roadmap.md](docs/06-roadmap.md)).
- **No independent audit.** The code was generated by AI and has only been checked by the author's own review and tests.
- **A compromised PC is out of scope.** Malware, keyloggers or an attacker with administrator rights on your PC can read what you type and what is on screen while the vault is unlocked. The screen-capture exclusion and the automatic clipboard clearing are best-effort measures, not guarantees.
- **Secrets can remain in memory as text.** The master key and passwords are kept in zeroed buffers where possible, but text typed or shown on screen (a key file's text, a displayed password, the clipboard) passes through .NET strings, which cannot be wiped reliably.
- **Imported CSV files contain your passwords in plain text.** The app can delete the file after import, but a normal delete may be recoverable from the disk. Delete browser exports securely and do not keep them in synced folders.
- **A key file saved as PDF is a plain-text copy.** Print the backup QR code on paper; the app warns if you choose a file-output printer, but cannot always tell.
- **Unsigned executable.** The distributed `Secrypt.exe` is not code-signed, so Windows SmartScreen may warn on first launch. Compare the files with `SHA256SUMS.txt` in the package.
- **One PC, one vault file.** There is no multi-PC sync or merge. If the file is changed elsewhere while it is open, the save is refused instead of overwriting.
- **Post-quantum security is not a goal of the current design.** It has only been evaluated, not implemented ([docs/07-mceliece-evaluation.md](docs/07-mceliece-evaluation.md)).

## 日本語

### 脆弱性の報告

Secrypt は、コードをすべて生成 AI で作成した個人の趣味のプロジェクトで、**第三者によるセキュリティ監査は受けていません**。制作者による**サポートや返信までの期限の約束はなく**、報告に返信や修正ができない場合があります。

それでも報告する場合:

1. このリポジトリで有効なら、GitHub の **Private vulnerability reporting**（「Security」タブ → 「Report a vulnerability」）を使ってください。
2. 無効な場合は、**攻撃手順や実データを書かずに** Issue を立て、「セキュリティに関する報告がある」とだけ書いてください。詳細はその後にやり取りします。

実際の保管ファイル（`*.pwmv`）、鍵ファイル（`*.pwmk`）、復旧コード、PIN、パスワード、個人情報を含むログは、決して投稿しないでください。

対象は最新のリリースだけです。[ライセンス](LICENSE)（MIT）に従って、自分でフォークして修正して構いません。

### 対象範囲

Secrypt は、**保管ファイルだけ、またはパスワードだけが漏れても開けない**こと、TPM の PIN をオフラインで総当たりできないことを目指して設計しています。設計と限界は [docs/02-threat-model.md](docs/02-threat-model.md) と [docs/03-key-management.md](docs/03-key-management.md) に書いています。すでに侵害された PC（マルウェア、キーロガー、管理者権限で付けられたデバッガ）に関する報告は、次のとおり対象外です。

### 既知の制限（Known limitations）

大切なものを預ける前に、必ず読んでください。

- **解錠方法を削除しても、主鍵は変わりません。** 解錠方法の削除（たとえば失くした鍵ファイル）、復旧コードの作り直し、PIN の変更をしても、保管ファイルの主鍵はそのままで、古い開け方の情報がファイルから外れるだけです。**削除前の保管ファイルのコピー**と、**削除した方法の秘密**（失くした鍵ファイル＋そのパスワード、古い復旧コード、同じ PC での古い PIN）がそろうと、その古いコピーを開けられます。そこで得られる主鍵は、今の保管ファイルも開けてしまいます。
  - この PC 内の自動バックアップ（`vault.pwmv.bak1`〜`.bak5`）は、これらの操作のときに Secrypt が削除します。確認画面でも先に伝えます。
  - **アプリの外にあるコピー**（クラウド同期、ファイル履歴、外付けディスクへのバックアップ）は削除できません。鍵を失くした・見られたおそれがある場合は、自分で削除してください。
  - 主鍵の作り直し（新しい鍵ですべてを暗号化し直すこと）は**まだ実装していません**（予定。[docs/06-roadmap.md](docs/06-roadmap.md)）。
- **第三者による監査は受けていません。** コードは AI が生成したもので、制作者自身のレビューとテストで確かめているだけです。
- **侵害された PC は対象外です。** マルウェア、キーロガー、PC の管理者権限を持つ攻撃者は、解錠中に入力した内容や画面の内容を読めます。画面キャプチャの除外とクリップボードの自動消去は、できる範囲の対策であり、保証ではありません。
- **秘密がテキストとしてメモリに残ることがあります。** 主鍵やパスワードは、可能な限りゼロ化するバッファで持ちます。ただし、入力・表示するテキスト（鍵ファイルのテキスト、表示中のパスワード、クリップボード）は .NET の文字列を通るため、確実には消せません。
- **取り込んだ CSV にはパスワードが平文で入っています。** 取り込み後にアプリが削除できますが、通常の削除ではディスクから復元できる場合があります。ブラウザから書き出したファイルは確実に削除し、同期されるフォルダには置かないでください。
- **PDF で保存した鍵ファイルは、平文のコピーです。** 予備の QR コードは紙に印刷してください。ファイルに出力するプリンターを選ぶと警告しますが、見分けられないこともあります。
- **署名のない実行ファイルです。** 配布している `Secrypt.exe` にはコード署名がなく、初回起動時に Windows SmartScreen の警告が出ることがあります。パッケージ内の `SHA256SUMS.txt` と照合してください。
- **1 台の PC に 1 つの保管ファイルです。** 複数 PC での同期や統合はありません。開いている間に別の場所でファイルが更新された場合は、上書きせずに保存を中止します。
- **量子コンピューター時代の安全性は、今の設計の目標ではありません。** 評価はしましたが実装はしていません（[docs/07-mceliece-evaluation.md](docs/07-mceliece-evaluation.md)）。
