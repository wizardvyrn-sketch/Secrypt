# 06. ロードマップ

## Phase 0: 技術 PoC（リスクの高い所から潰す）

| # | 検証項目 | 成功条件 |
|---|---|---|
| P0-1 | TPM: PCP で非エクスポート RSA 鍵作成 → 32B 秘密の暗号化/復号、PIN 要求、ロックアウト挙動 | 管理者権限なしで動作。PIN 連続失敗でロックされる |
| P0-2 | （FIDO2 キー入手後に延期）FIDO2: `webauthn.dll` で hmac-secret / PRF の決定的出力取得 | YubiKey で決定的な 32B が得られる |
| P0-1b | TPM シール: TBS（TSS.MSR）で sealed data object を作成し、PIN（authValue）付きで封印・解除。ロックアウト挙動 | 管理者権限なしで動作。採用可否で ADR-0004 を確定 |
| P0-2b | パスキー PRF 調査: Windows Hello パスキー / スマホ（ハイブリッド接続）で `webauthn.dll` から PRF 出力が取れるか | 取れれば `passkey` スロットとして追加検討 |
| P0-3 | Windows Hello: `KeyCredentialManager` 署名の決定性確認 | 同一チャレンジで同一署名。再登録で変わることを確認 |
| P0-4 | Argon2id / XChaCha20-Poly1305 を NSec で動かし、テストベクタ一致 | 既知ベクタ一致、所要時間計測 |
| P0-5 | SecretBuffer（pinned + VirtualLock + Zero）とクリップボード除外フォーマット | ダンプ上で秘密が残らない（ProcDump で確認） |

成果物: `poc/` 配下に各検証の最小コード＋結果メモ。ADR を確定させる。

## Phase 1: MVP

- Core: Vault フォーマット v1、キースロット（tpm / keyfile / recovery。fido2 はキー入手後）、アトミック保存・世代バックアップ
- App: 初期セットアップウィザード（復旧コード検証込み）、解錠、一覧/検索/編集、生成、クリップボード、自動ロック
- スロット管理画面（追加・削除・健全性表示）
- CI: ビルド・テスト・CodeQL
