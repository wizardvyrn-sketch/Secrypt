# ADR-0007: 秘密を記録しない構造化ログを入れる

- Status: Accepted（2026-10-25、D-4 は推奨案で決定）
- Date: 2026-10-25

## Context
MVP にはログがなく、利用者の PC で「開けない」「保存できない」が起きても原因を追えない（R-17）。
一方、パスワードマネージャのログに秘密や利用者データが残ると、それ自体が流出経路になる。

## Decision
- `Microsoft.Extensions.Logging` と自前の JSONL ファイル出力（ローカルのみ、14 日保持）。
- ログはイベントごとの型付きメソッドだけで出し、秘密・利用者データ（タイトル・URL 等）は記録しない。パスはユーザー名部分を伏せる。
- 既知の秘密を使った一連の操作のログに、それらが含まれないことを確かめる「カナリアテスト」を CI で常時実行する。
- 詳細は [10. デバッグ・ログ仕様](../10-debug-logging.md)。

## Consequences
- ＋ 解錠失敗の理由（PIN 違い・TPM クリア・破損）や保存の衝突を後から追える。
- ＋ 秘密が混ざらないことをテストで担保できる。
- − ログに出せる情報が限られるため、項目を特定した調査はできない（意図した制約）。
