## 4. 手動デバッグ（本番と同じ KDF 設定での通し実行）

リポジトリ外の小さなプログラムで、Application 層のサービスを本番の設定（鍵ファイル: Argon2id 256 MiB × 3、PIN・復旧コード: 64 MiB × 2）で動かした。
TPM はソフトウェアで模擬（Linux のため）。所要時間はこのコンテナでの値で、利用者の PC では異なる。

| 操作 | 所要時間 |
|---|---|
| STEP 1 TPM 封印（PIN） | 163 ms |
| STEP 2 鍵ファイル作成 | 806 ms |
| STEP 3 復旧コード作成 | 121 ms |
| 保存して解錠 | 57 ms |
| CSV 500 件の解析 → 取り込みの保存 | 30 ms → 26 ms |
| 項目の更新保存 20 回（合計） | 131 ms（1 回あたり約 7 ms） |
| PIN で解錠 | 162 ms |
| 鍵ファイルで解錠 | 739 ms |
| 復旧コード（小文字・空白区切り）で解錠 | 122 ms |
| PIN 間違い | 126 ms → WrongPin |

- 500 件のファイルサイズは 89 KB。保存は 10 ms 程度で、項目の保存に処理中の覆いを出さない判断は妥当。
- ログ 88 行。操作 ID で「UnlockStarted → SaveCompleted（最終使用日、counter 22 のまま・バックアップなし）→ SlotUseRecorded → UnlockSucceeded」を追えることを確認。
- ログ・設定ファイルを PIN・パスワード・復旧コード（区切りあり／なし）で検索 → **見つからない**。設定ファイルにあるのは鍵ファイルの場所（パス）だけ。

`pwm` の出力（抜粋）:

```
$ pwm diag vault
状態: ヘッダを読めました（ファイル形式 v1）
※ 鍵を使わないため、改ざんの検知（MAC の検証）と、暗号化された本体（項目・本体の形式の版）の確認はできません。
保存回数: 22
解錠方法: 3 件  ·  方針（復旧コード＋他 1 つ以上）: OK
  - Tpm      f50d4198-…  「TPM + PIN」  登録 2026-10-25  最終使用 2026-10-25  KDF 64 MiB × 2
  - Keyfile  26629aed-…  「鍵ファイル（USB）+ パスワード」  …  KDF 256 MiB × 3
  - Recovery 113b93ba-…  「復旧コード」  …  KDF 64 MiB × 2
$ pwm backups
  現在  保存回数 22 / .bak1 21 / .bak2 20 / .bak3 19 / .bak4 18 / .bak5 17
$ pwm logs
  88 行
     1 件  Warning 2201 UnlockFailed (WrongPin)
```

手動デバッグで気づいた点:
- `pwm diag vault` の「形式 v1」が本体形式（v2）と紛らわしい → 「ファイル形式 v1」に変え、本体は確認できない旨を明記（B-18）。
- 20 回続けて保存すると、取り込み前の状態のバックアップが残らない（世代数 5 のため）。仕様どおりだが、手書きメモから続けて登録する使い方（F7b）では早く押し出される → 改善提案 P-03。

| B-01 | 検（R-02） | 鍵ファイル作成などの処理中に自動ロックがかかると、破棄後の Vault に書き込む | 例外・登録の消失 | ロックを処理の完了まで保留（R0 で暫定、R2 で VaultSession に移管） | S13 |
