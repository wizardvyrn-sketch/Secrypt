# PoC 結果: TPM シール（P0-1b）

- 実施日: 2026-10-25
- 実行環境: Windows 11（10.0.26300）、AMD fTPM（ファームウェア 3.92）、.NET 10.0.13、**一般ユーザー権限（管理者ではない）**
- プログラム: `poc/TpmSealPoc`（TSS.MSR / Microsoft.TSS 2.1.1）
- 判定: **全項目成功 → ADR-0004（TPM シール方式）を採用**

## 結果

| 項目 | 結果 | 詳細 |
|---|---|---|
| TBS 接続 | ✅ | 管理者権限なしで接続できた |
| TPM 情報 | ✅ | 製造元 AMD（fTPM）、ファームウェア 3.92 |
| DA（総当たり対策）設定 | ✅ | 失敗カウンタ 0 / 上限 31 回、600 秒ごとに 1 減少 |
| SRK (0x81000001) | ✅ | Windows が作成済み（RSA、nameAlg SHA-256） |
| 封印（TPM2_Create） | ✅ | 26 ms、private blob 158 B |
| Unseal（パスワードセッション） | ✅ | 16 ms、秘密が一致 |
| Unseal（HMAC セッション＋応答暗号化 AES-128-CFB） | ✅ | 23 ms、秘密が一致 |
| 間違った PIN を拒否（1 回だけ試行） | ✅ | `TPM_RC_AUTH_FAIL` で拒否、DA カウンタ 0 → 1 |
| 間違えた後も正しい PIN で Unseal | ✅ | 成功 |
| 封印データの保存と読み戻し | ✅ | 保存ファイルから Unseal できた |
| **再起動後の Unseal** | ✅ | 17:11 に保存 → 17:15 に再起動 → 17:17 に `verify-saved` で一致を確認 |

## 分かったこと

1. **一般ユーザー権限で TPM シールが使える。** Windows の TBS は Create / Load / Unseal を許可しており、アプリに管理者権限は不要。
2. **Windows 既定の SRK（0x81000001）をそのまま親に使える。** 自前で CreatePrimary する必要がない（オーナー認証値は Windows が保持していないため、むしろ使えない）。
3. **PIN の総当たりは TPM が止める。** 31 回失敗でロックアウト、カウンタは 10 分に 1 回しか減らない。
   → 1 日に試せるのは約 144 回が上限。4 桁 PIN（1 万通り）でも全探索に約 70 日、6 桁なら約 19 年。
   PIN は Argon2id も併用するため、TPM を物理的に持ち去っても高速な総当たりはできない。
4. **封印データは対称鍵で保護される。** 封印データ（private blob）は親（SRK）の内部シードから導出した対称鍵で暗号化されており、
   SRK が RSA であっても封印データの保護は公開鍵暗号に依存しない（量子計算機による Harvest Now, Decrypt Later の対象外）。
5. **性能は十分。** 封印 26 ms、Unseal 16〜23 ms。Argon2id（数百 ms）が支配的で、TPM 部分は体感に影響しない。

## 本実装に向けた注意点

| 項目 | 方針 |
|---|---|
| セッション | パスワードセッションは PIN 由来値がバス上を平文で流れる。**HMAC セッション＋パラメータ暗号化を使う**（PoC で動作確認済み） |
| HMAC セッションの残余リスク | 非ソルトの HMAC セッションは、バスを盗聴された場合に通信内容から PIN のオフライン総当たりが理論上可能。fTPM（CPU 内蔵）はバスが外に出ないため実質問題なし。dTPM 環境向けにはソルト付きセッションを Phase 2 で検討 |
| DA 設定 | 上限 31 回は PC 全体で共有（Windows Hello の PIN 等と共通）。アプリ側でも連続失敗時は待ち時間を入れ、TPM のロックアウトを招かないようにする |
| PIN 失敗時の UI | `TPM_RC_AUTH_FAIL` は「PIN が違う」、`TPM_RC_LOCKOUT` は「ロック中（時間をおいて再試行、またはキーファイル／復旧コードで解錠）」と区別して表示 |
| 再起動後の確認 | 実施済み（成功）。DA カウンタは再起動後も 1 のまま（電源が入っている時間で減るため） |
| TPM クリア・BIOS 更新 | TPM がクリアされると SRK が変わり封印データは使えなくなる。**これが TPM スロット単独にしない理由**であり、キーファイル／復旧コードで解錠して TPM スロットを再登録する |
