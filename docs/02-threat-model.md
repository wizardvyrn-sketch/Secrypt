# 02. 脅威モデル

## 1. 守る資産

- A1: 保存しているパスワード・メモ（Vault 本体）
- A2: Vault Master Key (VMK)
- A3: 解錠要素（PIN/パスワード、FIDO2 キー、TPM 鍵、復旧コード）

## 2. 攻撃シナリオと対策

| # | シナリオ | 攻撃者が得るもの | 対策 | 結果 |
|---|---|---|---|---|
| T1 | Vault ファイル流出（クラウド/USB/バックアップ） | ファイル | VMK はランダム 256bit。各スロットの KEK は TPM/FIDO2/復旧コードの高エントロピー秘密を必須とする | **復号不可**（総当たり対象が 2^128 以上） |
| T2 | T1 + マスターパスワード流出 | ファイル＋PW | PW は KEK の片方の材料にすぎない。ハードウェア秘密がないと KEK を作れない | **復号不可** |
| T3 | PC 盗難（電源OFF） | ファイル＋TPM | TPM スロットは PIN 必須。TPM のアンチハンマリングで PIN 総当たりを数十回でロック | PIN が漏れていなければ実質不可 |
| T4 | FIDO2 キー盗難 | キー | キーの PIN（デバイス側で8回失敗でロック）＋アプリ側パスワード。さらにファイルも必要 | 不可。気づいたら該当スロットを失効 |
| T4b | USB キーファイルの盗難・コピー | キーファイル | アプリ側パスワード（Argon2id 重め）が必要。Vault ファイルも必要。気づいたらスロット削除（2026-11-01: 削除・復旧コードの作り直し・PIN の変更（TPM の登録し直し）時に、古い方法で開ける PC 内の自動バックアップ .bak1〜 も削除し、PC の外のコピーは画面で注意喚起）。VMK ローテーションは未実装（Phase 2） | PW が強ければ実質不可。**コピーに気づけない点は FIDO2 より弱い**（残余リスク）。**VMK を作り直さないため、削除前の保管ファイルのコピー（同期・ファイル履歴・外部バックアップ）と、紛失した鍵ファイル＋PW（または処分した古い復旧コード）がそろうと、今の保管ファイルも開ける**（残余リスク。Phase 2 の VMK ローテーションで解消） |
| T4c | キーファイルを Vault と同じ場所に置いてしまう | ファイル＋キーファイル | 登録時・解錠時に同一フォルダ/同一同期フォルダを検出して警告。QR 印刷でファイル出力の仮想プリンター（PDF・XPS・OneNote 等）を選ぶと警告（2026-11-01）。最後に使った鍵ファイルの場所は settings.json に DPAPI で暗号化して保存（2026-11-01） | 運用ミスを抑止 |
| T5 | 紙の復旧コード盗難 | コード | 金庫等で物理保管。任意で Shamir 2-of-3 に分割し単一紙では不足にする。ファイルも必要 | 保管次第。分割で緩和 |
| T6 | Vault の改ざん（スロット差し替え・ロールバック） | 書き込み権限 | ヘッダ全体を AEAD の AAD に含める。単調増加カウンタ（＋任意で TPM NV カウンタ） | 改ざん検知。ロールバックは警告 |
| T7 | 他ローカルプロセスからの UI 乗っ取り | 同一ユーザー権限のプロセス | Web UI/ローカル HTTP を使わない。ポート待受なし。IPC なし | 攻撃面自体を作らない |
| T8 | クリップボード盗聴 | クリップボード | 自動消去（既定 20 秒）、履歴/クラウドクリップボード除外フォーマット設定 | 緩和 |
| T9 | 画面キャプチャ | 画面 | `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`、パスワードは既定でマスク | 緩和 |
| T10 | 解錠中 PC のメモリダンプ / ページファイル | メモリ | ピン留め＋`VirtualLock`、使用後ゼロ化、自動ロック、ロック時に VMK 破棄 | 緩和（完全防御は不可） |
| T11 | サプライチェーン（依存ライブラリ汚染） | コード実行 | 依存を最小化（libsodium のみを暗号に使用）、バージョン固定、署名ビルド | 緩和 |
| T12 | 自分自身による鍵喪失（可用性の脅威） | — | 複数スロット必須、復旧コードの検証フロー、スロット健全性チェック | 防止 |

## 3. 想定外（スコープ外）とする脅威

正直に書いておく。以下はローカルのパスワードマネージャでは原理的に防げない。

- **解錠中のPCに管理者権限のマルウェアがいる**：キーロガー・メモリ読み取りで入力中/表示中の秘密は取られる。
  ただしハードウェアスロットにより「PW を盗んで後でファイルを持ち出して解く」型の攻撃は防げる（T2）。
- **TPM への物理攻撃**（バスのスニッフィング等）：dTPM はバス盗聴の研究例がある。
  セッション暗号化（TPM2 parameter encryption）を使う実装を優先し、残余リスクとして記録する。
- **強要（ゴムホース暗号解読）**。

## 4. 設計原則（脅威モデルから導かれるもの）

1. **ファイルに高エントロピー秘密を置かない**（T1, T2）
2. **人間が覚える秘密の総当たりはハードウェアに数えさせる**（T3, T4）
3. **攻撃面を作らない**：ネットワーク・ポート・プラグイン・ブラウザ依存なし（T7）
4. **可用性も脅威として扱う**：鍵喪失は「流出」と同じくらい致命的（T12）
