# ADR-0005: FIDO2 スロットは「保留機能」として実装し、キー入手時に有効化する

- Status: Proposed
- Date: 2026-10-25

## Context
FIDO2 キーは現在未所持だが、将来購入する予定。購入時にアプリの作り直しや Vault 形式の変更なしで使い始めたい。

## Decision
- Vault フォーマット v1 でスロット種別 `fido2` を **予約** し、パラメータ（`cred_id`, `rp_id`, `salt`, `credProtect`）の形を確定させておく。
- `Fido2SlotProvider` は実装するが、既定では **無効**（設定の「保留中の機能」に表示）。
- 有効化条件: 設定で有効化 **かつ** Windows WebAuthn API のバージョンが hmac-secret（または PRF）対応であること。
  条件を満たさない場合は理由を表示して有効化できないようにする。
- 有効化後の移行手順（ウィザード化）: 任意スロットで解錠 → FIDO2 キー#1 登録 → （任意）キー#2 登録 → keyfile スロット削除を提案。
- FIDO2 の実機テストはキー入手後に行う。それまでは単体テストは WebAuthn 呼び出しをモックして形式・フローのみ検証する。

## Consequences
- ＋ キー購入後、設定を切り替えるだけで導入でき、データの再暗号化は不要。
- ＋ 未検証のコードは既定で動かないため、MVP の安全性に影響しない。
- − 実機未検証のコードを抱えるため、有効化時に P0-2（実機 PoC）を必ず実施する。
