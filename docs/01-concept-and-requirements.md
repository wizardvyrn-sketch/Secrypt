# 01. 構想・要件

## 1. 背景と課題

一般的なローカル型パスワードマネージャ（KeePass 系など）は
「マスターパスワード → KDF → 暗号鍵」という構造をとる。このため:

- Vault ファイルが流出すると、攻撃者は **オフラインで無制限にパスワード総当たり** ができる。
  KDF（Argon2 等）で遅くはできるが、人間が覚えられる強度には限界がある。
- マスターパスワードが漏れた（肩越し・キーロガー・使い回し・メモ流出）時点で **即座に全部復号** される。
- マスターパスワードを「どこかに保存」すると、その保存先が新たな単一障害点・流出点になる。

本プロジェクトは **「マスターパスワードそのものを最終防衛線にしない」** 方式を検討する。

## 2. コンセプト

**「ファイル」「記憶」「物」の3つを分離し、どれか1つが漏れても復号できない」**

| 要素 | 例 | 流出時の影響 |
|---|---|---|
| ファイル | Vault 本体 | 単体では無価値（高エントロピー秘密を含まない） |
| 記憶 | PIN / パスワード | 単体では無価値（ハードウェアがないと使えない） |
| 物 | TPM（このPC）、FIDO2 キー、紙の復旧コード | 単体では原則無価値（PIN 併用 / 金庫保管） |

そして「確実に使える」ために **解錠経路を複数持つ**（1つ失っても他で開ける）。

## 3. ユースケース

| ID | ユースケース | 想定経路 |
|---|---|---|
| UC1 | 普段使いのPCで素早く開く | TPM + PIN（Windows Hello 顔/指紋でも可） |
| UC2 | 別のPCで開く | FIDO2 セキュリティキー + パスワード |
| UC3 | PCが壊れた / 買い替えた | FIDO2 キー or 復旧コードで開き、新PCの TPM スロットを再登録 |
| UC4 | FIDO2 キーを紛失した | 予備キー or 復旧コードで開き、紛失キーのスロットを失効 |
| UC5 | 全ハードウェアを失った（災害等） | 紙の復旧コード（または Shamir シェア 2-of-3） |
| UC6 | パスワードを忘れた | 復旧コードで開き、パスワードを再設定 |
| UC7 | Vault のバックアップ | 暗号化ファイルをそのままクラウド/USB にコピー（流出しても安全なので気軽に複製可能） |

## 4. 機能要件（MVP）

- F1: エントリ管理（タイトル、ユーザー名、パスワード、URL、メモ、タグ）、検索
- F2: パスワード生成（長さ・文字種・パスフレーズ）
- F3: クリップボードコピー（自動消去、クリップボード履歴/クラウド同期の除外）
- F4: 自動ロック（無操作タイマー、画面ロック/スリープ/ユーザー切替で即ロック）
- F5: キースロット管理（追加・削除・一覧、最低2スロットを強制）
- F6: 復旧コードの生成・印刷・検証（「本当に紙に書いたか」を確認する再入力ステップ）
- F7: CSV インポート（**Chrome / Edge のブラウザ保存パスワードが主**）、暗号化エクスポート
  - インポート後、元の CSV（平文）の削除を案内する
- F7b: 手書きメモからの移行用に、連続入力しやすい手動登録画面（Enter で次の項目へ、生成ボタン付き）
- F8: 自動バックアップ（世代管理、アトミック書き込み）

### 将来（MVP外）

- TOTP（2FA コード）表示
- ブラウザ自動入力（Native Messaging 経由。攻撃面が増えるため慎重に）
- 複数端末での同期（ファイル同期サービス任せ＋競合マージ）
- Shamir 秘密分散による復旧シェア

## 5. 非機能要件

| 区分 | 要件 |
|---|---|
| 機密性 | Vault 単体・パスワード単体・その両方の流出でも復号不可 |
| 可用性 | 単一の物（PC/キー）を失っても必ず開ける。スロット1つだけの状態を作らせない |
| 完全性 | ヘッダ・本体の改ざんを検知（AEAD + ヘッダを AAD に含める） |
| 動作環境 | Windows 11（TPM 2.0 必須要件があるため TPM 前提にできる） |
| ネットワーク | **通信なし**（外部送信ゼロ。テレメトリなし） |
| 攻撃面 | 待受ポートなし、ブラウザ非依存、外部プラグイン機構なし |
| メモリ | 秘密はピン留めバッファに置き、使用後ゼロ化。`string` に載せない |
| 監査性 | 暗号処理はコア層に集約し単体テスト・テストベクタで検証 |
